# 💻 编码规范

> 编写代码时应遵循的规则清单（Rule）。每一条均有真实故障/教训支撑。

---

## Rule 1：样式定位必须严格限定布局作用域，禁止过宽选择器污染相邻布局

**背景故障（2026-08-10 真实案例）**
`src/ui/styles/card.css` 的卡片样式原先使用 `div[custom-index="card"]` 作为选择器，仅靠属性命名区分。当同一文档同时存在「列表布局」与「超级块卡片布局」两类索引时，该选择器可能与列表中的超级块容器、卡片容器互相干扰，导致列表的层级缩进 / 分栏外观被卡片样式（背景、边框、内边距、`margin-bottom`）污染。

**强制写法**
对影响文档正文的样式，选择器必须同时限定到「块类型」+「布局」两层，例如：

```css
/* ✅ 正确：限定单卡片超级块（custom-index 标记 + NodeSuperBlock 类型 + row 布局） */
.protyle-wysiwyg div[custom-index="card"][data-type="NodeSuperBlock"][data-sb-layout="row"] {
    ...
}

/* ⚠️ 反例：仅靠属性名，可能命中列表内的容器甚至其它布局的节点 */
.protyle-wysiwyg div[custom-index="card"] {
    ...
}
```

**适用范围**
- 特殊布局（卡片、看板、徽标）的样式一律加 `[data-type="..."]` 与（如适用）`[data-sb-layout="..."]` 限定
- 列表布局（`NodeList`/`NodeListItem`）**永远不要**应用卡片/看板专用样式
- 看板间距由 Index Root（`custom-index="board"` + `data-sb-layout="row"`）的 CSS Grid `gap` 统一控制，禁止再切 `{{{col` 分栏
- 卡片自身不要写死 `margin-bottom` 来充当栅栏间距，避免 Grid 行高和间隙叠在一起

**判定清单（写样式前自查）**
1. 该选择器会命中哪些 `data-type`？
2. 是否会命中与目标布局正交的相邻布局？
3. 间距是否可上提到容器层级统一？

## Rule 2：任何"看似完善"的优化必须先评估副作用，宁可回退也不带回归

**背景教训（2026-08-10 真实案例）**
- 设置面板「懒挂载」：条件渲染看似能减少初始实例化，但会在此前全挂载策略下销毁 DataTab/BuilderTab 的内部状态（数据库列表、查询历史），切换回重建反而更慢 → **审慎放弃，回退全挂载**
- 自动更新「预写指纹」：在更新函数可能提前 `return`（如自动更新关闭、无数据）的路径上先落盘指纹，会导致"永远不再刷新" → **改为刷新成功后落盘**

**强制流程**
1. 涉及状态 / 缓存 / 生命周期 / 并发时，先列出副作用清单
2. 与现有策略比较（如"全挂载保状态"是既有意图，不要为微优化打破）
3. 无法彻底排除回归时，优先回退到改动前基线
