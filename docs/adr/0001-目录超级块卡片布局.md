# ADR 0001：目录超级块卡片布局

## 状态

已采纳（2026-08-10）；栅栏自适应修订（2026-08-17）

## Context

Users want an Index presentation with icon, title, and summary — not only ordered/unordered lists. Existing settings already split **list markers** (`listType`) and **link shape** (`linkType`). Folding those into one select would create conflicting semantics and break auto-update config merge.

v1 used a fixed `col` count and nested `{{{col` containers. That cannot wrap with editor width. Child Lists inside cards also made heights uneven; they are out of scope until a later design.

## Decision

Introduce a third orthogonal setting **`layoutType`**:

- `list` (default) — current behavior
- `superblock-card` — Superblock Card layout as a **flat CSS Grid fence**

### Scope (v1)

- **In:** Insert Index only (当前文档子文档目录)
- **Out:** Notebook Index, Outline, nested Child Lists inside cards

### Superblock Card rules

1. **Card body:** one content superblock per **direct child document**: optional Cover Image (`title-img`) → title row (optional icon + title via `linkType`) → optional Summary. No Child List.
2. **Icon:** still gated by existing `icon` switch; off → title + summary only. Cover Image is independent of the icon switch.
3. **Summary:** first non-empty top-level paragraph plain text, truncate to **80** chars; if missing, omit the summary row (no placeholder).
4. **Hierarchy:** only the current document’s immediate children become cards. Deeper docs are omitted for now. `depth` / `fold` / `listType` have no effect on this layout.
5. **Fence (栅栏):** all cards are **direct children** of one Index Root `{{{row` (`custom-index="board"`). No nested `{{{col`. CSS Grid `repeat(auto-fill, minmax(min(240px, 100%), 1fr))` wraps with editor width; same-row cards `align-items: stretch`.
6. **`col`:** removed. Not in settings UI, not written to `custom-index-create`, not compared in the update-config dialog. Stale `col` in plugin data / old IAL is dropped on next save or update.
7. **Settings UI:** when `layoutType` is `superblock-card`, hide 列表类型 / 目录深度 / 折叠层级. Those keys are still merged and persisted so switching back to list keeps local values.
8. **Auto-update:** wrap all cards in an **Index Root Container**; persist layout config inside `custom-index-create` on that root only; replace the whole root on update (old nested-col boards flatten on next refresh).

### Settings copy (zh)

- Title: 布局样式
- Options: 列表 / 超级块卡片

## Consequences

- Generator and render strategy gain a `layoutType` branch; list path stays default.
- Summary fetch adds per-document (or batched SQL) reads of the first non-empty paragraph — watch performance on large trees.
- Local config key checks for Index must include `layoutType` and must **not** include `col`.
- Later Notebook/Outline card layouts, and nested child-document presentation, need separate ADRs.
